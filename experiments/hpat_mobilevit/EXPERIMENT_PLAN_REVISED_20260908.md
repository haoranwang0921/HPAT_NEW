## 1. 本次修订的硬约束

### 1.1 暂不引入官方权重

本轮实验不下载、不加载 MobileViT 官方预训练权重，也不把 ImageNet/下游准确率作为评价指标。

当前允许使用：

- MobileViT 的公开模型结构/代码，用于生成真实算子图和张量 shape；
- pretrained=false 的 FP32 trace；
- 固定随机种子、固定输入和固定算子活动，用于时延、能耗、带宽、缓存和编程事件分析。

当前不允许声称：

- 量化后分类精度；
- 官方 checkpoint 下的精度保持；
- 官方权重对实际光子误差的鲁棒性；
- 结果代表真实手机、真实 NPU 或实测设备。

本轮实验目标收敛为：

> 在同一真实 MobileViT 算子图和统一硬件成本模型下，识别 HPAT/LPWM 系统中影响端到端时延与能耗的主要硬件和数据流参数，并确定可复现的优化方向。

## 2. 实验问题与最终回答形式

### RQ1：当前联合配置的主要瓶颈是什么？

需要把端到端时延和能耗拆分为：

- 外存/HBM 兼容记账；
- SRAM/NoC 搬运；
- MRR 编程；
- DAC 编码；
- 光学计算；
- ADC 转换；
- signed reduction；
- 激光与 MRR hold 静态能耗；
- 电子计算与电子静态能耗。

### RQ2：哪些参数对结果影响最大？

对每个参数分别进行单因素扫描，保持 trace、映射、随机种子和其他硬件配置不变，分别计算：

- 最大时延相对变化；
- 最大能耗相对变化；
- warm/cold 差异；
- 是否改变 HPAT 与 D0 的优劣关系；
- 是否只是降低功率而牺牲时延。

最终不能只展示一组最优结果，必须给出影响因素排序。

### RQ3：推荐采用什么优化方案？

推荐必须同时考虑端到端时延、单帧能耗、平均功率、光子面积、SRAM/编程代价、证据强度以及是否依赖未验证的器件假设。

## 5. Phase 2：单因素参数敏感性扫描

目标：得到最终“参数影响排序”的原始证据。

### 5.1 固定条件

所有单因素扫描必须固定同一 MobileViT-XXS FP32 trace、输入尺寸、batch、随机种子、signed mapping、算子映射范围、P0 其余参数和 cold/warm 执行协议。

每个点至少保存 cold frame 和 warm frame；正式排序至少基于 warm frame，并把 cold/warm 差异单独报告。

### 5.2 参数与建议扫描等级

| 参数 | 扫描等级 | 当前中心点 | 主要回答 |
|---|---|---:|---|
| 权重 SRAM | 0.5 / 1 / 2 / 25 MiB | 25 MiB | 缓存阈值和权重 DMA 是否主导 |
| 物理阵列 | 16×16 / 32×16 / 16×32 / 32×32 | 32×32 | 阵列扩展的时延—能耗—面积折中 |
| 光子频率 | 2.5 / 5 / 10 GHz | 10 GHz | 降频是否只降功率、是否增加静态积分 |
| 外存带宽 | 32 / 64 / 128 GB/s | 64 GB/s | 外存搬运是否成为端到端瓶颈 |
| 编程响应时间 | 10 ps / 100 ps / 1 ns / 10 ns | 10 ps | 10 ps 假设是否决定结论 |
| 编程并行度 | 1 / 4 / 16 / 32 | 4 | 编程通道是否已进入饱和区 |
| DAC/ADC 能耗 | 0.5× / 1× / 2× / 4× | 1× | 光电边界成本的敏感度 |
| DAC/ADC 时间 | 0.5× / 1× / 2× | 1× | 转换时间是否掩盖光学计算收益 |
| 静态功耗 | 0.5× / 1× / 2× | 1× | 激光、MRR hold、电子待机的影响 |
| 映射范围 | D0 / H1 / H2 / H3 | H3 | 增加光子化算子是否值得 |
| tile/core 组织 | 1×4 / 2×2 / 4×1 / 4×2 | 2×2 | 层级组织与核数的影响 |

说明：

- 早期 512 GB/s 外存只作为历史对照或单独的反事实点，不能与当前 64 GB/s P0 混称。
- 25 MiB SRAM 是当前联合点的容量，不代表所有模型都需要 25 MiB。
- 若某个扫描等级当前代码或器件模型无法支持，必须标记为“未建模”，不得用插值结果替代。

### 5.3 影响度量

对每个参数 p 计算：

    Latency sensitivity S_L(p) = max |L(p_i) - L0| / L0
    Energy sensitivity  S_E(p) = max |E(p_i) - E0| / E0
    Power sensitivity   S_P(p) = max |P(p_i) - P0| / P0

最终排序不使用一个未经解释的总分，而是同时给出：

1. 时延影响排名；
2. 能耗影响排名；
3. 功率影响排名。

如需给出综合排序，使用明确标注的辅助分数：

    S_joint = 0.5 × S_L + 0.5 × S_E

该分数只用于排序辅助，不能替代时延—能耗 Pareto 图。

### 5.5 当前已有先验，只作待验证假设

已有硬件扫描显示以下趋势，但它们必须在 Phase 1 账本修正后重新确认：

| 参数变化 | 已有 warm 结果趋势 | 暂定解释 |
|---|---|---|
| 16×16 → 32×32 | 时延 −26.91%，能耗 +23.19% | 阵列扩展换取时延，代价是光子静态/写入/面积 |
| 16×16 → 32×16 | 时延 −20.03%，能耗 −0.24% | 可能是更好的时延—能耗折中 |
| 1 → 2 MiB SRAM | 时延 −17.58%，能耗 −6.86% | 越过缓存阈值后减少 DMA 启动 |
| 0.5 MiB SRAM | 时延 +50.09%，能耗 +19.54% | 缓存不足导致权重搬运和替换 |
| 5 → 2.5 GHz | 时延 +22.72%，能耗 +8.57% | 静态能耗积分抵消降频收益 |
| 64 → 32 GB/s 外存 | 时延 +23.22%，能耗 +8.22% | 外存搬运有明显影响 |
| 4 → 8 cores | 时延 −10.74%，能耗 +20.46% | 并行度增加但共享搬运/静态开销上升 |

这些数字不是最终结论，最终表必须来自统一的 Phase 1 账本和同一版本的扫描结果。

## 6. Phase 3：候选优化方案组合验证

目标：从 Phase 2 的影响排序中选择少量有证据支持的组合，不进行无边界搜索。

### 6.1 候选方案

至少比较以下方案：

| 方案 | 核心变化 | 目的 |
|---|---|---|
| C0 | 当前 P0：32×32 / 10 GHz / 25 MiB | 统一参照 |
| C1 | 32×16 / 10 GHz / 25 MiB | 保留高频和大缓存，降低阵列能耗/面积 |
| C2 | 32×16 / 10 GHz / 2 MiB | 检验“达到缓存阈值即可” |
| C3 | 32×32 / 10 GHz / 2 MiB | 区分阵列收益与大 SRAM 收益 |
| C4 | P0 + DAC/ADC 优化账本参数 | 检验光电边界成本 |
| C5 | P0 + 编程并行度/响应时间优化 | 检验编程瓶颈是否已饱和 |

若 Phase 2 证明某一参数的影响很小，则从组合实验中删除该参数并记录删除理由。

### 6.2 推荐判据

优先推荐满足以下条件的方案：

1. 相对 C0 时延下降；
2. 能耗不增加，或增加幅度有明确系统收益；
3. 不依赖未验证的器件可实现性；
4. 对 DAC/ADC、MRR 编程和 SRAM 账本有完整证据；
5. 在 cold 和 warm 两种状态下结论方向一致；
6. 至少在 XXS 上可复现，且不把 XXS 结果外推到 XS/S。

推荐输出分为三类：

- 默认推荐：综合时延、能耗和可实现性最均衡；
- 低延迟推荐：允许更高能耗/功率，用于明确的时延目标；
- 低能耗推荐：优先能耗和面积，允许一定时延增加。
