# 小行块供数与结果回收交错：完整QKV算子验证

日期：2026-09-08。有效结果目录：row_pipeline_qkv_v2。v1为同一实现的初始扫描，v2增加关闭核内重叠的归因对照，没有覆盖旧结果。

## 实现

新增独立RowPipeline类，默认H1/H3入口不变。对每个物理权重块，按M维切为1/4/16/64/576行。每个行块的DAG为：输入读取→核内正负两段计算→部分和读取→数字差分及累加→部分和写回。输入读取和结果回收共用scratch_bus，只在任务依赖已完成且资源空闲时仲裁，按就绪FIFO顺序调度，不提前预约未来总线时段。不同资源允许同时执行，因此其他核心可以在数字归约期间使用总线。

每核一个行块信用：当前块回写完成后才允许下一块供数，保证有限输入/输出缓存。K维累加按同一batch、N块和行范围串行依赖。每波四核仍保持原权重遍历顺序，全部权重准备完成后进入行块阶段，波间排空；没有权重预取跨波重叠，也没有广播。三级内部仍沿用未校准的单向量服务时间，正负段之间排空。

## 协议

XXS首个真实QKV Linear：op_00076，M=576、K=64、N=192，7077888 MAC；32×32物理阵列、4核、10GHz、24个权重块；每模式冷启动/预热各一帧。外存64GB/s、片上256GB/s、权重缓存25MiB、激活scratch8MiB，保留HPAT原电子残余参数。隔离算子的上游依赖置空，但仍显式计入输入DRAM加载。非整网测量，非统计重复实验。

## 归因

1. 不能称“分行本身带来5%”：新仲裁下整块+核内流水也达到14.795810us。
2. 16行关闭核内重叠仍接近最佳，说明细粒度供数/回收与多核心交错已经掩盖大部分计算时间；开启核内重叠只进一步节省约14.208ns。
3. 16行可用8KiB而非288KiB额外缓冲取得相同名义性能。小行块的直接价值包括降低缓冲需求，不是只看时延。
4. 总线搬运仍为瓶颈。降低粒度不减少传输字节，不能预期出现三级流水线的整算子3倍加速。

## 校验

- 54项回归测试通过，包括新增的FIFO仲裁、尾部M/K/N块、不同分块粒度的流量/能耗守恒和容量不足拒绝测试。
- 9种模式、18帧完成；事件与DAG记录保存。
- 所有模式逐帧各用途传输字节与原串行一致。
- 原有动态计算、存储、写环能耗逐项一致；总能量差异来自时长缩短后的静态积分。
- 检查每个任务的全部前驱完成、资源不重叠、输入就绪、token三级链、权重未提前覆盖、数字归约等待转换及部分和依赖。
- 缓冲容量按保守的每核预留上界计入scratch容量；不是无限输出队列。

## 限制

新增仲裁/缓冲控制成本和每小事务固定开销尚未计入；因此能耗下降不是完整电路级净节能结论。特别是1行方案对每事务开销敏感。未进行INT8数值执行、bias/再量化补齐或真实器件启动间隔校准。现有资源模型仍未区分tile内外拓扑。这是完整单算子调度验证，不是H1/H3整网收益。

源代码：experiments/hpat_mobilevit/row_pipeline.py；运行入口：experiments/hpat_mobilevit/run_row_pipeline.py；测试：experiments/hpat_mobilevit/tests/test_row_pipeline.py。comparison.csv为全部结果，各模式config/summary/events及row模式nodes记录可供复核，provenance.json含配置和源代码哈希。
