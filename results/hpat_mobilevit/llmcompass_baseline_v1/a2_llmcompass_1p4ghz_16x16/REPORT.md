# LLMCompass 电子基线 A2（移动级：1.4 GHz / 16×16）

日期：2026-09-10　｜　工具：LLMCompass（ISCA'24）+ SCALE-Sim 2.0.2

## 配置（用户指定）

| 参数 | A2 | 对比 A1（原 A） |
|---|---|---|
| 核数 | 4 | 4 |
| 频率 | **1.4 GHz** | 10 GHz |
| 脉动阵列 | **16×16 INT8** | 32×32 INT8 |
| 峰值算力 | **1.4336 TMAC/s** | 40.96 TMAC/s（28.6×） |
| 片上缓冲 | 25 MiB @ **256.2 GB/s** | 25 MiB @ 260 GB/s |
| DRAM | 64 GB/s | 64 GB/s |

**带宽处理说明**：`global_buffer_bandwidth_per_cycle_byte` 由 26 改为 **183**，以在 1.4 GHz 下保持片上 ~256 GB/s（与 P0 口径一致）。DRAM 64 GB/s 不变。若希望带宽随频率等比下降，需改回 26 B/cycle。

**语义变化**：A2 **不再与 HPAT P0 同频同阵列**。它表示"与 HPAT 共享存储系统的移动级电子加速器"——1.4 GHz 与 16×16 更贴近真实手机 NPU，因此作为移动端对照比 A1 的 10 GHz 更现实。

## 结果（XXS warm）

| 口径 | 数值 (ms) |
|---|---:|
| **A2** LLMCompass 1.4 GHz / 16×16 | **0.395301** |
| A1 10 GHz / 32×32 | 0.186645 |
| B A100 级 | 0.013816 |
| 当前 D0（手写 roofline 总时延） | 0.492209 |
| 当前 D0（仅计算项） | 0.079280 |
| HPAT H3（P0 冻结） | 0.799543 |

覆盖 97.28% MAC（83 算子 / 204,318,464 MAC），覆盖外 = 7 个 depthwise（2.72%）。能量不可用（`heuristic-GPU` 不设 `energy`）。

## 头条：小阵列的利用率高一个数量级

| | 峰值 (TMAC/s) | 实测 (TMAC/s) | **占自身峰值** |
|---|---:|---:|---:|
| A1 32×32 @10 GHz | 40.96 | 1.095 | **2.7%** |
| A2 16×16 @1.4 GHz | 1.4336 | **0.517** | **36.1%** |

- A2 峰值只有 A1 的 **1/28.6**，但实测时延只慢 **2.12×**（0.3953 vs 0.1866）。
- 原因：A2 的利用率比 A1 高 **13.4×**。MobileViT 的 K/N 很小（K 常见 16–64、N 常见 16–48），32×32 阵列大部分时间是半空的；16×16 反而几乎填满。
- ⇒ **在这批形状上，"阵列开得更大/更快的"并不划算**；吞吐量被填充率支配，而不是被峰值支配。
- 与 HPAT 光子阵列的墙钟利用率 5.4% 相比：A2（36.1%）明显更高，A1（2.7%）更低——**说明"利用率低"不是光子独有的问题，而是形状与阵列尺寸匹配的问题**。

## 对 HPAT 的含义

| 对照 | HPAT H3 相对该基线的倍数 |
|---|---:|
| vs 手写 D0（10 TOPS 标量） | 1.62× 慢 |
| vs A1（同规格 32×32@10GHz） | 4.28× 慢 |
| **vs A2（移动级 16×16@1.4GHz）** | **2.02× 慢** |

即：换成**更贴近真实移动 NPU** 的电子基线后，HPAT 的差距从 4.28× 收窄到 **2.02×**，但仍未胜出。

## 边界

- A2 是参数覆盖得到的模型，非流片/实测设备。
- 逐算子串行求和（保守）；不含算子间重叠。
- 能量不可用；仅 XXS；depthwise 与向量/归一化算子不在覆盖内。
- 片上带宽按 256 GB/s 保持，此为一处显式假设（见上）。

## 复现

```
python -B -m experiments.hpat_mobilevit.run_llmcompass_baseline --config a2 --models xxs \
  --out-root results/hpat_mobilevit/llmcompass_baseline_v1/a2_llmcompass_1p4ghz_16x16
```
