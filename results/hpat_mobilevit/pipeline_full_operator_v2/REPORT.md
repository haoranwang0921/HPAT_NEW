# 完整QKV算子供数与归约接入验证

XXS首个QKV Linear：M=576、K=64、N=192，共7077888 MAC。物理32×32、四核、10GHz，24个权重块，正负两段输入。沿用HPAT原电子侧参数；无跨算子依赖，输入通过实际DRAM事件加载。与原串行算法同配置比较，冷/热各一帧。

供数和归约现已接入：保留权重读取/写环、全部分块输入读取、数字差分与K累加、部分和回写、最终外存输出。没有删减活动事件以制造收益。核心内部使用三级独立资源，每向量完整阶段依赖，单槽输出信用反压；正负两段之间排空。完整波的有限输入/输出缓冲额外预留294912字节（288KiB），计入8MiB scratch容量。额外缓冲控制及新增访问能耗尚未校准，报告能量沿用现有访问账本。

结果解释：原调度逐核心预约整块输入传输，再统一预约归约；总线串行占用使较早完成的核心仍需等待。单核心计算提速被总线关键路径隐藏。预热服务时间：两符号输入读取3.456us，部分和读取5.184us、写入3.456us，归约0.774144us；外存输入0.679us、输出1.828us。服务时间可能重叠，不应相加作为独立关键路径证明。

检查：49项现有回归测试通过；原串行执行方式仅抽取为execute_core_block方法，默认行为保留。新路径独立验证每token三阶段、输入就绪、权重不覆盖、归约不早于转换、部分和链；两种模式对应传输字节与动态能耗一致。单token、慢ADC、输入等待及单槽信用检查通过。

边界：这是供数/归约已计入的完整单算子“整块缓冲”集成，并非逐行供数/转换/归约全流水线。bias/requantization成本缺项仍继承原模型；并未验证数值INT8精度。不能报告整网加速。下一步应实现有限行块的共享总线公平仲裁、输出队列反压和按行归约，而非直接把块级时间除以3。

有效目录v2；v1报告写出错误已标识。主H1/H3入口不会自动启用新子类。
