# Security policy

## Supported versions

Security fixes are accepted for the latest `1.0.x` artifact release. Historical
experiment snapshots and local run directories are not supported releases.

## Reporting a vulnerability

Please use the repository's private **Security** reporting interface (Security
Advisories, then **Report a vulnerability**). Do not open a public issue for a
suspected vulnerability or include credentials, private datasets, host paths,
device logs, or identity information in a report.

Include the affected version, a minimal reproduction, impact, and any suggested
mitigation. Maintainers will acknowledge a complete report when the anonymous
account is next active, assess whether the artifact or its dependency lock is
affected, and coordinate a disclosure-safe fix. No response-time guarantee is
made during double-blind review.

The security channel is for vulnerabilities in the released software and
workflow. Scientific disagreements, reproducibility questions, and evidence
limitations belong in ordinary issue discussion and must still preserve the
anonymous-review boundary.
